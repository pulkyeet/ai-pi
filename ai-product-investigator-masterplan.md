# AI Product Investigator: Masterplan

*Supersedes the earlier brief. No timeline or execution phases by design.*

**One line:** Type a product idea, get an evidence backed discovery report in under three minutes, where every sentence in it traces to a dated character span in a fetched page.

---

## 1. Why

**The problem.** Validating a product idea today is six hours of tab shuffling across Product Hunt, Reddit, G2, GitHub and competitor pricing pages, ending in a subjective gut call. The data exists. Nobody wants to collect and reconcile it.

**Why now.** The bottleneck was never reasoning. It was retrieval plus normalisation across heterogeneous, contradictory, undated sources. That is now automatable at a few cents per run.

**Who it is for.** Indie hackers, early stage founders, PMs scoping a new bet, hackathon teams, junior analysts.

**Why it is a strong portfolio artifact.** Most AI projects are `prompt -> LLM -> answer`. This is planning, parallel tool use, extraction, entity resolution, evidence grading, contradiction resolution, constrained synthesis and cost control. The interview sentence is: *"It produces a research report where no sentence can be published unless it is bound to a specific character span in a specific fetched page, and I can show you the drill down."*

## 2. What

### Input
Free text. Example: `"AI expense tracker for freelancers"`.

### Output contract

```json
{
  "run_id": "r_01J...",
  "query": "AI expense tracker for freelancers",
  "brief": {
    "category": "expense management",
    "segment": "B2B, freelancers and micro SMB",
    "geography": "global",
    "monetisation_guess": "seat based SaaS",
    "field_confidence": {"segment": 0.55, "geography": 0.40}
  },
  "competitors": [
    {
      "entity_key": "web:expensify.com",
      "display_name": "Expensify",
      "maturity": "established",
      "positioning": "...",
      "pricing": {"model": "seat", "entry_usd_month": 5, "free_tier": true},
      "claim_ids": [1204, 1207, 1233]
    }
  ],
  "pricing_landscape": {"median_entry_usd_month": 12, "spread": [0, 49], "claim_ids": [...]},
  "pain_points": [
    {"theme": "manual receipt categorisation", "support_count": 23,
     "distinct_threads": 7, "grade": "D", "confidence": 0.61, "claim_ids": [...]}
  ],
  "feature_gaps": [...],
  "contradictions": [
    {"entity_key": "web:expensify.com", "attribute": "pricing.entry_usd_month",
     "values": [{"v": 5,  "src": 88,  "grade": "A", "as_of": "2026-07-30"},
                {"v": 18, "src": 142, "grade": "C", "as_of": "2025-11-02"}]}
  ],
  "mvp": {"statement": "...", "addresses_finding_ids": [12, 19, 27]},
  "risks": [...],
  "coverage": {"score": 0.82, "failed_branches": ["funding"]},
  "freshness": {"median_source_age_days": 41, "oldest": "2025-03-11"},
  "meta": {"cost_usd": 0.031, "duration_s": 128, "sources_fetched": 64, "cache_hit_rate": 0.31}
}
```

### Four hard rules

1. **Every prose sentence carries at least one `claim_id`.** Sentences that cannot be bound are dropped, not flagged.
2. **An entity is only listed if it has a verifiable public artifact**: a 200-responding URL, an existing repo, a real package, a live store listing. No artifact, no listing. This eliminates hallucinated competitors structurally rather than by prompting.
3. **`confidence` is computed, never generated by a model.** Formula in 5.6.
4. **`coverage` is reported separately from confidence.** A run whose funding branch died says so, out loud, on the report.

### Explicitly out of scope
Dollar market sizing (unverifiable, pure hallucination surface). GTM strategy (generic on any input). Team accounts, sharing, saved workspaces.

## 4. Architecture

### 4.1 Planner: typed, not free form

The planner does not write arbitrary steps. It selects from a fixed registry and allocates budget:

```python
TASKS = {
  "discover_competitors": {"args": ["query_variants"],       "cost_weight": 3},
  "profile_product":      {"args": ["entity_key"],           "cost_weight": 2},
  "extract_pricing":      {"args": ["entity_key"],           "cost_weight": 1},
  "mine_community":       {"args": ["keywords", "venues"],   "cost_weight": 4},
  "oss_profile":          {"args": ["repo"],                 "cost_weight": 1},
  "find_funding":         {"args": ["entity_key"],           "cost_weight": 1},
  "trend_signals":        {"args": ["keywords"],             "cost_weight": 2},
}
```

Output is a schema validated DAG:

```json
{"nodes": [{"id": "t1", "kind": "discover_competitors",
            "args": {...}, "budget_weight": 3}],
 "edges": [["t1", "t2"]], "total_budget_weight": 40}
```

It is still planning rather than scripting. The planner decides *whether* to mine Reddit, *how many* competitors to profile, *whether* GitHub is relevant to this category, *whether* funding matters. But the space of decisions is enumerable, validated, and replayable. Free form planning is precisely where these systems become undebuggable.

### 4.2 Executor: asyncio DAG over a Postgres task table

`asyncio.TaskGroup`, one semaphore per external service (search 4, crawl 8, LLM 6). Per task timeout. Three retries with jittered exponential backoff, only on 429, 5xx and timeouts.

**Leasing.** Multiple workers, no broker:

```sql
begin;
select id from tasks
where status = 'pending' and run_id = $1
order by priority
limit 1
for update skip locked;
-- set status='running', lease_token=gen_random_uuid(),
--     lease_expires_at = now() + interval '2 minutes'
commit;
```

`skip locked` is the whole trick. Without it a second worker blocks on the row the first just locked. With it, it shrugs and takes the next one.

**Crash recovery** is one sweep on worker startup:

```sql
update tasks set status = 'pending', lease_token = null, lease_expires_at = null
where status = 'running' and lease_expires_at < now();
```

**Idempotency**, which the leasing scheme makes mandatory. A worker that hangs past its lease will be superseded, then wake up and try to write anyway. Two guards:

```sql
-- 1. completion is rejected if the lease was lost
update tasks set status='done' where id=$1 and lease_token=$2;
-- 0 rows affected  ->  discard the work, do not write claims

-- 2. belt and braces on the claims table
unique (run_id, source_id, attribute, char_start)
-- writes use ON CONFLICT DO NOTHING
```

**Partial failure is the normal case.** A dead branch reduces `coverage`, it does not fail the run.

**Budget enforcement** is a counter in the dispatch loop:

```python
spent = 0
async with asyncio.TaskGroup() as tg:
    for task in pending(run_id):
        if spent + task.cost_weight > run_budget:
            mark_skipped(task, "budget")
            continue
        tg.create_task(execute(task))
        spent += task.cost_weight
```

The cap exists to protect against **your own bugs**, not against token cost. A retry storm or a fan out to 200 profile tasks is the failure mode being insured against.

The executor sits behind one interface, `Executor.submit(plan) -> AsyncIterator[Event]`, so it can be swapped later without the pipeline noticing.

### 4.3 Data model

```sql
users(id, email UNIQUE, created_at, quota_override, is_admin)
identities(id, user_id, provider, provider_user_id, UNIQUE(provider, provider_user_id))

runs(id, user_id, query, brief jsonb, status, cost_usd, coverage numeric,
     is_benchmark bool, is_public bool, started_at, finished_at)

tasks(id, run_id, kind, args jsonb, status, priority, attempts,
      lease_token uuid, lease_expires_at, cost_usd, latency_ms, error)

sources(id, canonical_url UNIQUE, root_key, fetched_at, http_status,
        content_hash, extracted_text, retrieval_reason, ttl_expires_at)

entities(id, entity_key UNIQUE, display_name, maturity, meta jsonb)
entity_aliases(entity_id, alias_key UNIQUE)

claims(id, run_id, entity_id, attribute, value_text, value_num, unit, as_of,
       source_id, quote, char_start, char_end, grade, extractor_version,
       confidence numeric, superseded_by,
       UNIQUE(run_id, source_id, attribute, char_start))

findings(id, run_id, kind, statement, claim_ids int[], support_count, confidence)
reports(id, run_id, payload jsonb)
```

`findings` is the only table whose text ever reaches a user, and it always carries `claim_ids`. That single constraint is the entire drill down mechanism.

### 4.4 Fixed claim vocabulary

Free form attributes make cross entity comparison and contradiction detection impossible. The vocabulary is closed:

```
pricing.model            (seat|usage|flat|freemium)
pricing.entry_usd_month
pricing.free_tier        (bool)
pricing.trial_days
product.launch_date
product.platforms
product.integrations
feature.<slug>.present
company.funding_total_usd
company.stage
oss.repo | oss.stars | oss.stars_90d_delta | oss.last_commit_at
oss.license | oss.contributors_90d
complaint.<theme>
request.<theme> | request.<theme>.reactions
```

### 4.5 Entity identity

The canonical key is scheme prefixed, because plenty of real products have no domain of their own:

```
web:expensify.com
web:ai-expense-reporter.fly.dev
gh:owner/repo
npm:pkg   |  pypi:pkg
chrome:<ext-id>  |  ios:<app-id>  |  hf:user/space
ph:<slug>          # pre-launch, Product Hunt only
```

For `web:` keys, resolution uses the Public Suffix List, which already knows that PaaS hosts are multi tenant:

```python
extract = tldextract.TLDExtract(include_psl_private_domains=True)
extract("ai-expense-reporter.fly.dev").registered_domain
# -> "ai-expense-reporter.fly.dev"   not "fly.dev"
```

Set that flag explicitly. The default has bitten people.

`entity_aliases` merges the same product arriving under different keys. Merge triggers: a repo's `homepage` field pointing at a domain, or a site footer linking back to a repo.

**Maturity tier**, derived from domain age, last commit, funding claims and store install counts:

```
established | funded | indie | hobby | abandoned
```

This matters more than it looks. "Three funded competitors plus forty weekend projects" is a completely different answer for a founder than "forty three competitors," and once `.fly.dev` entities are accepted, the second is what a naive system would print.

### 4.6 Evidence grading and computed confidence

| grade | source type | examples |
|---|---|---|
| A | structured primary | pricing page, API docs, GitHub API, package registry counts |
| B | prose primary | changelog, company blog, Wayback snapshot of a primary |
| C | third party aggregator | G2, Capterra, Crunchbase, StackShare |
| D | community anecdote | one Reddit or HN comment, one GitHub issue |

```python
BASE = {"A": 0.90, "B": 0.75, "C": 0.55, "D": 0.35}

def confidence(best_grade, n_distinct_domains, age_days, contradicted):
    base    = BASE[best_grade]
    multi   = 1 + 0.05 * min(n_distinct_domains - 1, 4)
    decay   = 0.98 ** (age_days / 30)
    penalty = 0.6 if contradicted else 1.0
    return min(base * multi * decay * penalty, 0.97)
```

Deterministic, tunable, explainable, and capped below 1.0 so the system never claims certainty.

**Promotion thresholds** turn anecdotes into findings:

- Reddit and HN themes: at least 5 supporting comments across at least 3 distinct threads.
- GitHub issues: reaction weighted instead, so one issue with 47 thumbs up clears the bar where one Reddit comment never does.

The report prints the real N. No invented "3,248 comments."

### 4.7 Contradiction detection is SQL

```sql
select entity_id, attribute, array_agg(distinct value_num), count(*)
from claims
where run_id = $1 and superseded_by is null and grade in ('A','B','C')
group by entity_id, attribute
having count(distinct value_num) > 1;
```

Resolution: highest grade wins, ties broken by most recent `as_of`. The loser is **retained and surfaced**, because "pricing page says $5 last week, a 2025 review says $18" is genuinely useful signal, not noise to be swept up. This only works because claims are typed, which is the entire justification for the closed vocabulary.

### 4.8 Extraction: never trust model reported offsets

Models fabricate character positions. The extractor asks for the **exact verbatim quote** and the span is located locally:

```python
idx = source_text.find(claim.quote)
if idx == -1:
    drop(claim, reason="quote_not_in_source")
claim.char_start, claim.char_end = idx, idx + len(claim.quote)
```

If the quote is not literally present in the fetched text, the claim never exists. This one rule is what makes "every sentence binds to a span" true rather than aspirational, and it works with any model.

One page per extraction call. Do not batch pages into the 1M context window: it wrecks span attribution and makes every retry expensive.

### 4.9 Constrained synthesis

The MVP, gap and risk generators receive **only the resolved finding set**, never raw page text. They must emit `addresses_finding_ids`. Validation rejects output referencing fewer than three findings, or zero findings from the complaints category.

This is the guard against generic advice, which is the standard failure mode of this entire product category.

### 4.10 Streaming

SSE event types: `plan.created`, `task.started`, `task.completed`, `task.failed`, `finding.added`, `report.ready`. The frontend renders the plan as a live checklist. People tolerate two minutes when they can see what is happening. They abandon a spinner at twenty seconds.

## 5. Source registry

**Tier 1, always**

| source | yields | access | grade |
|---|---|---|---|
| own site `/pricing`, `/plans`, `/docs`, `/changelog` | pricing, features, launch | direct fetch, path guessing | A |
| AlternativeTo | explicit competitor graph | scrape | C |
| Product Hunt | launch date, tagline, upvotes | GraphQL API, free token | B |
| HN Algolia | launches, sentiment, complaints | free API, no auth | D |
| Wayback CDX | historical pricing, "when did X ship" | free API | B |
| GitHub | see below | REST/GraphQL, 5k req/hr with PAT | A / D |

**Tier 2, planner gated**

| source | yields | reality |
|---|---|---|
| G2, Capterra, GetApp, TrustRadius | reviews, pricing bands | heavy anti bot. Read via SERP snippets, do not crawl |
| SaaSHub | alternatives | scrapeable |
| StackShare | tech stack, adoption | scrapeable |
| Reddit | complaints | search only, never bulk |
| Stack Exchange API | dev pain points | free API |
| npm, PyPI, crates.io | download counts as adoption proxy | free APIs, exact numbers, grade A |
| Chrome Web Store, App Store, Play | installs, ratings, review complaints | installs B, reviews D |
| HuggingFace | models and spaces for AI native categories | free API |
| Wellfound | headcount, stage | scrapeable |

**Tier 3, funding, genuinely hard for free.** Crunchbase is effectively paywalled. Substitutes: SEC EDGAR full text and Form D (US, real numbers), UK Companies House API, Wikidata, OpenCorporates. Coverage will be patchy. Report it as a coverage gap rather than guessing.

**Trend.** Wikipedia pageviews API, plus HN and Reddit post volume over time computed from search results already in the pipeline. Better than pytrends, which breaks constantly.

### GitHub specifically

It is the best *structured* pain point source available, better than Reddit for anything developer adjacent:

- `is:issue label:enhancement sort:reactions-desc` is a literal feature request leaderboard with counts and permalinks
- star velocity over 90 days, not total stars, is the real adoption signal
- last commit, release cadence and issue close rate give a liveness and abandonment read
- `awesome-<category>` repos are hand curated competitor sets, very high precision seeds
- license determines whether an OSS incumbent can be competed with or simply forked

Planner gated. "Does this category plausibly have OSS competitors" is exactly the kind of decision that justifies having a planner at all.

## 6. LLM layer

**Model:** `deepseek/deepseek-v4-flash` via OpenRouter, key held server side. Supports function calling, JSON schema structured output and prompt caching. Roughly $0.09 per million input and $0.18 per million output, with cache reads around $0.02 per million.

**Estimated run cost:** ~60 pages at ~4k tokens, plus ~30k output, lands around **$0.03 per run**. LLM spend is therefore not a constraint worth engineering against.

**Single model, not a routing ladder.** It is not a weak model (MMLU Pro 86.4, GPQA 88.1, SWE-bench Verified 79.0). Run everything on it, measure, and only route planning or synthesis upward if the benchmark shows an actual gap. The suspicion is that extraction is fine and synthesis is where it thins, but that is a hypothesis to test rather than a design to pre-commit to.

**Implementation notes**

- Structure every prompt so the static claim schema is the **prefix**, so prompt caching hits the largest repeated segment. Cache read at $0.02 versus $0.09 is roughly a 4x saving on the bulk of every extraction call.
- Pin providers with `require_parameters: true`, or use OpenRouter's Exacto routing mode on the extraction path. Otherwise a request can be routed to a backend that silently ignores `response_format`.
- Pydantic validation on every model response before anything touches the database. Never trust raw JSON.
- Fetched page content only ever enters a schema constrained extraction prompt whose output is restricted to the closed claim vocabulary. It never reaches a free text prompt. See 8.3.

## 7. Search layer

**Exa primary.** ($20 signup credit, $10/mo free usage — Brave's free tier was killed Feb 2026 and Google CSE is closed to new customers.)

The bigger lever is not the provider, it is volume. **Most of your searches should not be searches.** Once a domain is known, its pricing is not searched for, it is fetched at `/pricing`, `/plans`, `/pricing-plans`. Deterministic path guessing, zero credits. Search is reserved for discovery only, which should bring a run down to roughly 6 to 10 searches instead of 40.

Domain specific retrievers replace general search entirely where they exist: HN Algolia, GitHub, Stack Exchange, package registries.

Explicitly rejected: DuckDuckGo (no official API, the libraries scrape lite endpoints and return 202/403 under load), SearXNG self hosted (you inherit the blocking).

## 8. Access control, quotas and guardrails

### 8.1 Auth

Google OAuth and GitHub OAuth. Login is required to run anything.

- Logged out: full read access to the pre-baked benchmark reports on the homepage, including drill down. No live runs.
- Logged in: live runs, subject to quota.

Implementation: FastAPI plus Authlib, httponly `SameSite=Lax` session cookie. `users` keyed by email, `identities` keyed by `(provider, provider_user_id)`, so the same person arriving via Google and later GitHub with one email lands on one account.

No bring your own key. The unit economics do not require it, and accepting third party secrets on a public site with no security review is liability with zero upside. The escape hatch for a genuine power user is self hosting: the repo is open, keys go in `.env`.

### 8.2 Quota knobs

**All values are unset and must be configured before deployment.** They are deliberately left blank until benchmark runs produce real per-run search and latency numbers.

```python
RUNS_PER_USER_PER_DAY       = TBD
GLOBAL_RUNS_PER_DAY         = TBD
MAX_CONCURRENT_RUNS         = TBD
RUN_BUDGET_WEIGHT           = TBD   # executor fan out cap
RUN_BUDGET_USD              = TBD   # bug insurance, not cost control
RUN_TIMEOUT_S               = TBD
MAX_COMPETITORS_PROFILED    = TBD
MAX_PAGES_PER_ENTITY        = TBD
MAX_COMMUNITY_THREADS       = TBD
```

The one that matters is derived, not guessed:

```
GLOBAL_RUNS_PER_DAY  ≈  (monthly_search_credits / 30) / searches_per_run_p95
```

Use p95, not median. The tail is what drains a free tier.

Two things push the effective number up: source and search caches are shared across users, so a second query in an already explored category is close to free, and Exa's $10/mo free usage gives real overflow headroom.

### 8.3 Guardrails

| layer | mechanism |
|---|---|
| public surface | benchmark reports served from cache, instantly, zero cost. Most visitors never trigger a live run |
| bot filter | Cloudflare Turnstile before a live run |
| quota | per user per day, plus a global daily cap |
| concurrency | K concurrent runs, queue with visible position, so a burst cannot drain the search quota in 60 seconds |
| kill switch | on daily cap exhaustion the site serves reports only and says live runs resume tomorrow |
| input validation | 300 char cap, reject non product queries, reject obvious injection attempts, blocklist harmful categories |
| budget cap | per run spend and fan out ceiling, protecting against your own retry storms |

**Prompt injection arrives from crawled pages, not from users.** A competitor's site can carry text aimed specifically at research agents, and published work on generative engine optimisation shows model directed instruction is among the most effective attack surfaces against exactly this class of system.

The architecture is structurally resistant rather than filter dependent, and this should be stated explicitly in the README: page content only ever enters a schema constrained extraction prompt whose output space is the closed claim vocabulary, output that fails validation is dropped, and any quote not literally present in the source text is discarded. There is no path from page text to free text generation.

## 10. Benchmark set

Ten hand built queries, checked into the repo as YAML. There is no public benchmark for product discovery, so this set silently becomes the definition of every quality claim in the README.

```yaml
- id: q03
  query: "AI expense tracker for freelancers"
  difficulty: medium
  ground_truth:
    must_include: [expensify.com, ramp.com, wave.com, freshbooks.com]
    known_absent: [stripe.com]          # tests precision, not recall
    facts:
      - {entity: expensify.com, attribute: pricing.entry_usd_month,
         value: 5, verified_on: 2026-08-01}
```

**Composition rules**

- Span difficulty deliberately: roughly 3 easy ("project management tool"), 4 medium, 3 hard and thin ("MEV monitoring for solo validators", "WhatsApp first CRM for Indian SMBs"). Ten easy Western SaaS categories will produce a 95 percent recall figure that collapses on the first real query.
- Span shape, not just difficulty: one dev tools query that exercises the GitHub path, one consumer query where GitHub should correctly be skipped, one dominated by OSS incumbents, one where the category barely exists so the system can be checked for saying "no real competitors" instead of inventing four.
- Include at least one trap: a company that changed pricing recently, so a stale aggregator disagrees with the live page. Without it there is no evidence the contradiction detector ever fires rather than silently never triggering.

**Discipline**

- Ground truth decays. Date stamp every fact and re-verify before publishing any number.
- Split six for tuning, four held out and touched only at the end. Without this the README number is fiction told to yourself.

**Derived metrics:** competitor recall, precision proxy via `known_absent`, fact accuracy, sentence binding rate, contradiction detection firing rate, cost per run, p50 and p95 latency, cache hit rate.

**These same ten runs are the public homepage.** One artifact serves three purposes: quality measurement, instant recruiter demo, and the only pages a logged out visitor can read.

## 12. Decision log

**1. Orchestration: hand rolled asyncio DAG over Postgres.**
*Instead of:* LangGraph.
*Why:* the workload is fan out and fan in of independent stateless tasks with no cycles. LangGraph earns its weight on cyclic, stateful agent loops with mid graph interrupts, and disambiguation here happens at Stage 0 as an ordinary HTTP round trip, so its best feature never fires. Budget aware mid flight cancellation is a counter in a loop rather than graph topology. Debugging is a SQL query against a task table rather than a checkpoint blob. LangGraph is already on the CV via fAIth, so the keyword is banked and a second one adds nothing. The executor is the interesting engineering in this project, and delegating it turns the project into "wired up some nodes."
*Hedge:* it sits behind `Executor.submit(plan) -> AsyncIterator[Event]`, swappable if a genuine re-planning loop is ever added.

**2. Single model, no routing ladder.**
*Instead of:* cheap model for extraction, frontier model for planning and synthesis.
*Why:* at roughly $0.03 per run, cost optimisation solves a problem that does not exist, and V4 Flash is not a weak model. Routing is a config change through the gateway if the benchmark later shows synthesis quality lagging. Pre-optimising here is guessing.

**3. Search: Exa primary.**
*Instead of:* Brave, Google CSE, DuckDuckGo, SearXNG.
*Why:* Brave's free tier was killed Feb 2026 and Google CSE closed to new customers, so the originally planned providers no longer exist. DDG has no official API and its scraping libraries fail under load. SearXNG self hosted means inheriting the blocking. Exa's $20 signup credit plus $10/mo free usage covers this project's volume, and the "fetch `/pricing` instead of searching for it" optimisation keeps that volume low.

**4. Scheme prefixed entity keys with PSL private domains enabled.**
*Instead of:* bare registrable root domain.
*Why:* products legitimately live at `foo.fly.dev`, in a GitHub repo with no site, or as a Chrome extension. A bare root domain key would collapse every Fly-hosted product into one entity called `fly.dev`. The Public Suffix List already encodes which hosts are multi tenant, so this costs one constructor flag.

**5. Confidence is computed, not generated.**
*Instead of:* asking the model for a confidence score.
*Why:* `0.82` emitted by an LLM is decoration, and the first competent interviewer asks what it was calibrated against. A formula over grade, source count, age and contradiction status is deterministic, tunable, and defensible.

**6. Contradiction detection in SQL over typed claims.**
*Instead of:* asking a model to compare sources.
*Why:* it is a GROUP BY. It is free, deterministic, cannot hallucinate a contradiction, and cannot miss one. It is also the entire reason the claim vocabulary is closed.

**7. Verbatim quote plus local span lookup.**
*Instead of:* model reported character offsets.
*Why:* models fabricate offsets confidently. `text.find(quote)` either succeeds or the claim is dropped. This is the mechanism that makes the drill down promise real rather than aspirational.

**8. Mandatory OAuth to run, public benchmark reports to read.**
*Instead of:* anonymous free runs, or bring your own key.
*Why:* search credits are the scarce resource and anonymous runs cannot be quota'd meaningfully. Google and GitHub OAuth are one click for this exact audience. BYO key would not buy Brave credits anyway, so it solves nothing while making the site a secrets handler.

**9. Postgres task table instead of Celery plus Redis.**
*Why:* `SELECT ... FOR UPDATE SKIP LOCKED` plus a lease column is a concurrent queue with no broker. One fewer service, one fewer bill, and the whole run state is queryable with SQL during debugging.

**10. httpx plus trafilatura, Playwright only where forced.**
*Instead of:* Firecrawl everywhere.
*Why:* Firecrawl on every page is the single largest avoidable cost in a project like this, and roughly 80 percent of target pages are static HTML.

**11. Market sizing and GTM cut from scope.**
*Why:* neither can be grounded in a citable source. They are the two places where this product category reliably hallucinates, and including them would break rule 1.

**12. Planner emits a validated DAG from a fixed registry.**
*Instead of:* free form step generation.
*Why:* it keeps genuine planning (which sources, how many, whether at all) while remaining enumerable, replayable and injection resistant. Free form planning is where these systems become impossible to debug.

**13. Benchmark set doubles as the public homepage.**
*Why:* one artifact serves quality measurement, instant recruiter demo, and the logged out reading experience, and it keeps the demo cost at zero.

## 13. Risks

| risk | mitigation |
|---|---|
| hallucinated competitors | verifiable public artifact required, or the entity is dropped |
| generic MVP advice | synthesis constrained to cited findings, minimum three, at least one complaint derived |
| search quota exhaustion | path guessing over searching, shared caches, global daily cap, CSE overflow |
| aggregator anti bot (G2, Capterra) | read via SERP snippets, never crawl, grade accordingly |
| Reddit terms and rate limits | search based access only, short spans, link out, never mirror |
| injection from crawled pages | closed vocabulary extraction, schema validation, verbatim quote check, no free text path |
| stale claims read as current | `as_of` on every claim, age decay in confidence, freshness line on the report |
| low quality entities from PaaS domains | maturity tier, surfaced in the report |
| two minute wait feels broken | streaming plan checklist plus progressive findings |
| runaway fan out or retry storm | per run budget weight and spend caps |
